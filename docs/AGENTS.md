# Documentation-specific guidance

Start with [INDEX](INDEX.md) and [DOCUMENTATION](DOCUMENTATION.md). Root [AGENTS](../AGENTS.md) remains applicable.

Update the one owner of a rule; use links elsewhere. Preserve the difference between draft targets, approved behavior, implementation evidence, and release status. Do not promote the Slack-style feature review to approved merely because this structure is adopted.

For plan changes, follow [the lifecycle standard](plans/README.md). Existing numbered plans were moved without rewriting their evidence. The old paths are short forwarding notes, not editable second copies. Templates are not active initiatives.

Keep feature documents behavioral: scope, rules, permissions, failure states, acceptance, open decisions, and only current stable implementation entry points. Put detailed steps, commands/results, and decision history in the living plan. Do not create an ExecPlan for every documentation correction.

Update relative links, indexes, and code-to-specification pointers when moving files. Preserve attribution and meaningful history. Do not invent missing source text, test results, screenshots, production status, generated schemas, or numerical quality scores.

Run the documented structural checks after changes. Record unrelated inconsistencies in the debt tracker instead of rewriting every product document. Add a new category only when actual content needs an owner; do not scaffold empty architecture, audit, generated, or agent-role hierarchies.
