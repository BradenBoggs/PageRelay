# Marketing site and use-case pages

Status: discussed and prototyped direction; production marketing site is not implemented in this repository.

This document owns SideWire's public positioning, landing-page structure, service/industry use-case pages, truthful compatibility claims, and primary acquisition paths.

## Positioning

Primary promise:

> Add feature-rich team communication to the workplace apps and websites your team already uses.

Supporting position: SideWire creates one source of truth for communication across a team's tools instead of leaving tasks and conversations fragmented inside every service.

The product should be explained as a universal collaboration layer, not merely “comments on a webpage,” a CRM plugin, or a replacement for Slack and every task platform.

## Core landing page

The landing page should demonstrate the workflow visually:

1. open any supported work page;
2. open SideWire beside it;
3. see the conversation and tasks tied to that page;
4. find activity from every tool in one inbox.

Primary conversion actions may be install extension, start trial, or join a waitlist depending on actual availability. Never send a user to a nonexistent install or imply Chrome Web Store approval before it exists.

## Use-case and service pages

Create focused pages for real search and sales intent, such as collaboration for CRMs, design workflows, service-business platforms, and named services like Canva or SuperMove where lawful and useful.

Each page should:

- explain the specific communication problem in that workflow;
- show how the universal SideWire layer helps;
- use relevant screenshots or demos when available;
- link back to the horizontal product story;
- distinguish universal compatibility from a native integration;
- avoid claiming endorsement, partnership, data sync, or trademarks ownership.

Pages should contain genuinely adapted content rather than changing only a product name for SEO.

## Design direction

Use a clean, modern light design. Avoid a dark-first theme, generic AI gradients, excessive drop shadows, cartoonish cards around every section, and vague abstract copy. Show the side panel working beside recognizable but legally safe example workflows.

## Measurement

Track privacy-respecting acquisition source, page-to-primary-action conversion, install/start completion, activation, and qualified paid conversion. Do not optimize for page views alone. Referral attribution follows `referrals-and-partnerships.md`.

## Claims and launch states

Marketing copy must reflect actual availability:

- “works alongside” may describe verified universal page behavior;
- “integrates with” requires an implemented native integration or very clear explanation;
- “realtime,” “secure,” “private,” “AI,” and performance claims require evidence;
- pricing, trial, and referral claims must match active product configuration.

## Out of scope

A large content farm, copied competitor pages, fake testimonials, unapproved logos, unsupported comparison claims, and hundreds of thin autogenerated service pages are not acceptable launch tactics.
